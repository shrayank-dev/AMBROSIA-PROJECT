# Security policy

## Supported versions

Security fixes are currently prepared on the `main` branch. This is an experimental research project, so no service-level response time or production-security guarantee is offered.

## Reporting a vulnerability

Please do not publish exploit details, crash dumps, memory captures, credentials, tokens, or proprietary title data in a public issue. Use GitHub's private vulnerability reporting feature for this repository when available. If it is unavailable, open a minimal issue asking for a private reporting channel without including sensitive details.

Include the affected commit, operating system, build configuration, and a minimal synthetic reproducer when possible. Do not attach the Xbox title, game binaries, extracted assets, save data, or runtime caches.

## Scope

This policy covers Ambrosia source code, build tooling, tests, repository workflows, and documented runtime interfaces. It does not authorize testing against services, accounts, or proprietary software that the tester does not own or have permission to use.

## Disclosure

After a fix is available, maintainers will coordinate a disclosure timeline appropriate to the issue. Security reports and fixes must comply with applicable law, platform terms, and the licenses of affected components.
